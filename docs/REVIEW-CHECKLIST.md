# Legal and Academic Review Checklist

Use this checklist before submitting a new or revised study note for approval.

## A. Syllabus
- [ ] Subject, code, programme and admission batch are identified.
- [ ] Topic is in the applicable official syllabus or explicitly labelled additional context.
- [ ] Study-day organisation is not misrepresented as official university unit numbering.

## B. Legislation
- [ ] Provision number and statutory heading checked in the official Act.
- [ ] Definition and each material ingredient checked.
- [ ] Exceptions, explanations and provisos checked.
- [ ] Punishment provision and subsection checked separately.
- [ ] Amendments and commencement considered where relevant.
- [ ] IPC comparisons are labelled as legacy comparisons and not confused with BNS sections.

## C. Cases
- [ ] Case name, court, year and citation verified.
- [ ] Judgment or reliable report inspected.
- [ ] Principle accurately summarised.
- [ ] Relevance to current BNS wording explained.
- [ ] Unverified leads clearly labelled.

## D. Question bank
- [ ] Verified PYQ only if the actual paper was inspected.
- [ ] Paper year/session, programme, subject code and source recorded.
- [ ] Predicted and original practice questions clearly labelled.
- [ ] Question IDs are stable.
- [ ] Answer key checked independently.

## E. Teaching and exam readiness
- [ ] Simple English and beginner-friendly explanation.
- [ ] Examples clearly identified as illustrations.
- [ ] Long answer has structured introduction, rule, ingredients, application and conclusion.
- [ ] Short notes and comparison tables are accurate.
- [ ] Ambiguity or missing facts acknowledged.

## F. Repository
- [ ] Correct folder and canonical topic file.
- [ ] Dashboard/index links updated.
- [ ] Internal-link check passes.
- [ ] Subject changelog and root changelog updated.
- [ ] No confidential data or unauthorised copyrighted material.
- [ ] Pull request states limitations and exact changes.

## Release decision

Passing this checklist reduces errors but does not guarantee perfection. The repository owner reviews the final diff and decides whether to authorise the merge.
